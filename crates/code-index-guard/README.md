# code-index-guard

Нативный (Rust) `PreToolUse`-хук для Claude Code и Codex CLI, который держит дисциплину **code-index**: перенаправляет нативные `Read`/`Grep`/`Glob`/`Bash`/`PowerShell` по индексированным каталогам в инструменты code-index, но блокирует **только файлы, которые индекс действительно отдаёт**, — без тупиков на неиндексированных.

Отдельный маленький бинарник в составе рабочей области code-index: от ядра не зависит, читает `index.db` напрямую, старт **~3 мс**.

## Зачем

Правило «по индексированным репо ходить через MCP, а не нативным Read/Grep» живёт в системном промпте как текст и под нагрузкой деградирует — модель сползает на нативные инструменты. Хук — детерминированный гард, не зависящий от внимания модели.

## Логика: «блокирую только доказуемо-индексированное»

На каждый `Read`/`Grep`/`Glob`/`Bash`:

1. Путь **не** под индексированным префиксом → пропустить.
2. Под префиксом:
   - **Read** — открыть локальный `<repo>/.code-index/index.db` (rusqlite, read-only) и проверить членство:
     - текстовый файл (`text_files`) или код с сохранённым контентом (`file_contents.oversize=0`) → **deny** (redirect в `read_file`/`get_function`);
     - нет строки в `files` / `oversize=1` / голая строка → **пропустить** (MCP не отдаст);
     - локального `index.db` нет (federation-репо, индекс на ВМ) → **пропустить**;
     - ритуальный `Read(offset=1, limit=1)` для гейта Edit → **allow** (ровно одна первая строка).
   - **Grep / Glob / Bash (`grep`/`rg`/`find`/`ls`)** — repo-wide поиск/список → **redirect** в `grep_code`/`grep_text`/`list_files(repo)`. Бинарные расширения и несуществующие пути → пропустить.
   - **PowerShell** — тот же разбор, что у Bash, но по именам командлетов: `Get-Content` (`gc`/`cat`/`type`) пер-файлово → `read_file`; `Select-String` (`sls`), `Get-ChildItem` (`gci`/`ls`/`dir`), `findstr` repo-wide → `grep_code`/`grep_text`/`list_files`. Учитываются `-Path`/`-LiteralPath`, `-TotalCount`, `-Tail`, смена каталога через `Set-Location`/`sl`/`pushd`, а тела here-string'ов (`@'` … `'@`) выбрасываются как данные.

Принцип: гард смещён в «пропустить при сомнении» — false-negative (не поймал) безвреден, false-positive (заблокировал неотдаваемое) = дед-энд.

## Источник индексированных путей

В бинарнике путей нет — всё из конфига хука `code-index-guard.toml` (ищется **рядом с exe** или по env `CODE_INDEX_GUARD_CONFIG`). Все настройки необязательны:

1. **`daemon_toml`** — путь к `daemon.toml` индексатора; из него берутся все репо демона (env `CODE_INDEX_DAEMON_TOML` переопределяет).
2. **`[[local]]`** — отдельные репо, добавленные вручную (путь + алиас) — в дополнение к `daemon.toml` или вместо него.
3. **`events_db`** — база SQLite событий хука: одна строка на запуск (`deny` / `allow` / `skip`, причина, путь, инструмент) в таблице `hook_events`. По ней видно, что хук перехватил и что пропустил. Каталог базы должен существовать, файл создаётся сам. Нет ключа — события не записываются.

Итоговый список баз = репо из `daemon.toml` + `[[local]]` с **дедупликацией по пути**: `daemon.toml` приоритетен, `[[local]]` добавляет лишь отсутствующие в нём пути. Пусто в обоих (или файла нет) → индексированных путей нет, хук ничего не перехватывает. Шаблон — `code-index-guard.toml.example`.

## Сборка

Из корня репозитория code-index:

```bash
cargo build --release -p code-index-guard
```

Бинарник: `target/release/code-index-guard` (`.exe` на Windows). SQLite собирается вместе с крейтом (bundled), на Windows с gnu-toolchain нужен `gcc`/`dlltool` (например, из w64devkit в `PATH`).

## Установка

1. Скопировать exe → каталог хуков, например `~/.claude/hooks/code-index-guard.exe`.
2. Положить рядом `code-index-guard.toml` — скопировать из `code-index-guard.toml.example` и вписать путь к своему `daemon.toml` и/или отдельные репо в `[[local]]`. **Без конфига хук ничего не перехватывает**: путей по умолчанию нет.
3. В `~/.claude/settings.json` добавить **первым** `PreToolUse`-хуком (перед остальными):

```json
{
  "matcher": "Read|Grep|Glob|Bash|PowerShell",
  "hooks": [
    { "type": "command", "command": "C:/Users/<ВашеИмя>/.claude/hooks/code-index-guard.exe", "timeout": 10 }
  ]
}
```

Откат: убрать этот блок из `settings.json`.

## Режим `--list-roots`: список корней в контекст сессии

Тот же exe, запущенный как `code-index-guard.exe --list-roots`, печатает список индексированных
корней в формате `SessionStart`-хука — модель видит границы индекса **до** первого вызова и не
теряет ход на `deny`. stdin не читается, решения `PreToolUse` не принимаются.

Список берётся из той же функции, что решает про `deny`, — второго источника нет, поэтому снимок
не может разойтись с поведением хука. Нет конфига / нет `daemon.toml` / список пуст → **пустой
stdout** (пустой контекст лучше ложного), код возврата всегда `0`.

Регистрация в `~/.claude/settings.json` — блок `SessionStart` **без matcher**, чтобы срабатывать на
все виды старта (`startup`, `resume`, `clear`, `compact`):

```json
{
  "hooks": [
    { "type": "command", "command": "C:/Users/<ВашеИмя>/.claude/hooks/code-index-guard.exe --list-roots", "timeout": 10 }
  ]
}
```

Цена — около 2 КБ текста (~700 токенов) в каждой сессии.

## Смена каталога внутри команды

Цепочка команды разбирается по звеньям, и смена каталога меняет базу для последующих звеньев — поэтому `cd <репо> && grep -rn x src/` судится по настоящему рабочему каталогу, а не по каталогу сессии.

Распознаются `cd`, `pushd`, `Set-Location` (`sl`), `Push-Location` — с аргументом или без; `popd` и `Pop-Location` означают «каталог неизвестен». Путь раскрывается: `..` и `.` сворачиваются, `~` и `~/...` ведут в домашний каталог (`USERPROFILE`, иначе `HOME`), снимаются кавычки и ведущие ключи `-Path`/`-LiteralPath`/`/d`. С индексированным префиксом сравнивается уже **нормализованный** путь, поэтому `cd .. && ls src`, `cd ../other && ls src`, `cd ~/proj && ls src` выходят из индекса и не блокируются (раньше они отклонялись: `…/repo/../other` начинался с индексированного префикса).

Каталог оказался **неизвестен** (`popd`, `cd -`, нераскрытая подстановка `$VAR`) — гард воздерживается: подставлять прежний cwd нельзя, иначе отказ выносится по репозиторию, к которому команда не относится.

## Префикс имён инструментов

У Claude Code инструменты сервера code-index называются `read_file`, `grep_code`, `list_files`; у Codex — с префиксом: `mcp__code_index__read_file`. Модель должна видеть точное имя, а файл `code-index-guard.toml` **общий** для обоих клиентов, поэтому префикс задаётся ключом командной строки `--mcp-prefix <префикс>` в своей строке запуска. Пример для `~/.codex/hooks.json`:

```json
{ "type": "command", "command": ".../code-index-guard.exe --mcp-prefix mcp__code_index__", "timeout": 10 }
```

Ключ применяется ко всем текстам для модели: отказы `Read`/`Grep`/`Glob`/Bash/PowerShell и впрыск `--list-roots`. Без ключа тексты отказов **побайтно** прежние.

⚠️ Правка `~/.codex/hooks.json` сбрасывает доверие Codex к хуку — его надо поставить заново.

## Контракт хука

- **stdin**: `{ "tool_name", "tool_input", "cwd" }`
- **stdout**: `{"hookSpecificOutput": {"hookEventName":"PreToolUse","permissionDecision":"deny"|"allow","permissionDecisionReason":?}}` — либо ничего (воздержаться, решает следующий хук).
- **exit**: всегда `0`. Fail-safe: любая ошибка/паника → воздержаться.

Контракт тот же, что у хуков `PreToolUse` Claude Code, поэтому гард может звать и не клиент, а любая программа, которой нужно то же правило. Например, служба агентов, отдающая файлы своим агентам, перед чтением передаёт гарду `{"tool_name": "Read", "tool_input": {"file_path": …}, "cwd": …}` и исполняет его ответ.

## Производительность

~2.9 мс (без обращения к БД) / ~4.2 мс (с открытием `index.db`) на вызов. Проверка идёт только на путях под индексированным префиксом — остальные вызовы выходят рано.

## Ограничения (v1)

- **Пути в переменных оболочки раскрываются только при явном присваивании в самой команде**: `root="C:/repo"; grep -rn x "$root"` разбирается по настоящей цели. Если значение приходит извне (`$HOME`, `$(git rev-parse …)`, обратные кавычки), цель неизвестна — гард воздерживается, а не подставляет каталог сессии.
- Перехватываются только **чтение содержимого, поиск и обход каталога**. Всё остальное по индексированным путям идёт свободно и намеренно: запуск программ, сборка, `git`, `Copy-Item`/`Remove-Item`, правка через `Edit`/`Write`. Гард — про цену токенов, а не про доступ к файлам.
- Метаданные без содержимого не перехватываются ни в одной оболочке: `wc`/`file`/`stat` в Bash, `Get-Item`/`Test-Path`/`Measure-Object` в PowerShell — MCP такого не отдаёт, запрет был бы дед-эндом.
- Bash-ридеры `wc`/`file`/`stat` **не** перехватываются. `cat`/`head`/`tail` по одному файлу ловятся пер-файлово (с проверкой членства в индексе), repo-wide `grep`/`rg`/`find`/`ls` — редиректом в `grep_code`/`list_files`.
- Репо без локального `.code-index/index.db` (напр. каталог задан в `[[local]]`, но ещё не проиндексирован): пер-файловая проверка невозможна — `Read` пропускается, redirect работает только для repo-wide Grep/Glob/Bash.

## Тесты

- Модульные тесты: `cargo test -p code-index-guard`.
- Пробы на реальных вызовах (stdin JSON → решение хука): `python tests/probes/run_probes.py <exe> <code-index-guard.toml>`. Пути своей машины — в `tests/probes/paths.json` (образец — `paths.example.json`; сам файл в git не кладётся). Пробы запускают гард с копией конфига без `events_db`, поэтому в рабочую базу событий не пишут.
