# Установка вручную, по шагам (Windows)

[English](manual-install_EN.md)

Установка без скриптов и npm: скачать один файл, положить в папку, создать файл
настроек, запустить и подключить к клиенту ИИ (Claude Code, Cursor, VS Code и
другие клиенты MCP). Права администратора не нужны.

Автоматическая установка одной командой — `install.ps1`, см. [README](../README.md#установка).

## Как это устроено

Программа — один исполняемый файл. Он запускается в двух ролях:

| Процесс    | Команда                       | Что делает                                                         |
|------------|-------------------------------|--------------------------------------------------------------------|
| Индексатор | `bsl-indexer.exe daemon run`  | Читает исходники, строит индекс, следит за изменениями файлов      |
| MCP-сервер | `bsl-indexer.exe serve ...`   | Отвечает на запросы клиента ИИ                                     |

Оба процесса находят друг друга через папку, указанную в переменной окружения
`CODE_INDEX_HOME`.

HTTP-сервер встроен в сам `bsl-indexer.exe` — устанавливать IIS, nginx и другие
программы не нужно. Сервер слушает только адрес `127.0.0.1`, то есть доступен
лишь с этого компьютера; открывать порты или публиковать что-либо не требуется.

Подключить клиента ИИ можно двумя способами (шаг 6):

- **Вариант А — HTTP.** MCP-сервер работает постоянно, клиент обращается к нему
  по адресу `http://127.0.0.1:8011/mcp`. Один сервер на все окна клиента и все проекты.
- **Вариант Б — stdio.** MCP-сервер отдельно не запускают: клиент сам стартует
  `bsl-indexer.exe serve` при открытии сессии и общается с ним напрямую, без
  порта. Процесс завершается вместе с сессией.

**В обоих вариантах индексатор (`daemon run`) должен быть запущен.** MCP-сервер
только читает индекс; без индексатора на любой запрос приходит ответ
`daemon_offline` — даже если индекс уже был построен раньше.

## Шаг 1. Скачать архив

Откройте страницу последнего выпуска:
https://github.com/Regsorm/code-index-mcp/releases/latest

Скачайте один из файлов:

- `bsl-indexer-windows-x64.zip` — с поддержкой 1С:Предприятие (выгрузки Конфигуратора и EDT);
- `code-index-windows-x64.zip` — без 1С (Python, Rust, Go, Java, JS/TS и другие языки).

В архиве один файл: `bsl-indexer.exe` (или `code-index.exe`). Дальше в инструкции —
`bsl-indexer.exe`; для второй сборки подставьте `code-index.exe`.

## Шаг 2. Создать папку программы и положить файл

1. Создайте папку `C:\tools\code-index` (можно любую другую — тогда меняйте путь во всех шагах).
2. Распакуйте в неё `bsl-indexer.exe`.

Проверка — в командной строке:

```
C:\tools\code-index\bsl-indexer.exe --version
```

Должен напечатать номер версии, например `code-index 1.2.2`.

## Шаг 3. Задать переменную окружения CODE_INDEX_HOME

**Обязательно.** Без неё индексатор не запустится.

Вариант 1 — командой:

```
setx CODE_INDEX_HOME "C:\tools\code-index"
```

Вариант 2 — через окно: Пуск → «Изменение переменных среды для своей учётной записи» →
«Создать…» → имя `CODE_INDEX_HOME`, значение `C:\tools\code-index`.

После этого **закройте и откройте заново** окно командной строки — в старых окнах
переменная не видна. Клиент ИИ (VS Code, Cursor) тоже перезапустите.

## Шаг 4. Создать файл настроек daemon.toml

В папке `C:\tools\code-index` создайте текстовый файл `daemon.toml`
(кодировка UTF-8) и перечислите папки с исходниками — по секции `[[paths]]` на каждую:

```toml
[daemon]
http_host = "127.0.0.1"
http_port = 8015
log_level = "info"

[[paths]]
path = "C:/Repo1C"
alias = "main"

[[paths]]
path = "C:/Repo1C-2"
alias = "second"
```

- `path` — папка с выгрузкой конфигурации или проектом. Косые черты — прямые `/`.
- `alias` — короткое имя папки; клиент ИИ указывает его в каждом запросе.
- `8015` — порт индексатора. Занят — поставьте любой свободный.

## Шаг 5. Запустить и проверить

Окно 1 — индексатор:

```
C:\tools\code-index\bsl-indexer.exe daemon run
```

Окно 2 — MCP-сервер (только для варианта А; для варианта Б пропустите):

```
C:\tools\code-index\bsl-indexer.exe serve --transport http --port 8011 --config "C:\tools\code-index\daemon.toml"
```

Без `--config` сервер не возьмёт папки из `daemon.toml`.

Проверка в ещё одном окне:

```
C:\tools\code-index\bsl-indexer.exe daemon status
```

Ожидаемый вывод: `статус: running` и список папок. Отметка `[ready]` у папки —
индекс построен. Пока отметки нет — идёт первая индексация; на крупной
конфигурации она занимает заметное время, повторные запуски быстрые.

## Шаг 6. Подключить к клиенту ИИ

Добавьте блок в файл `.mcp.json` проекта (для Claude Code) или в настройки MCP
вашего клиента.

**Вариант А — HTTP** (MCP-сервер из окна 2 запущен):

```json
{
  "mcpServers": {
    "code-index": {
      "type": "http",
      "url": "http://127.0.0.1:8011/mcp"
    }
  }
}
```

Алиасы — из `daemon.toml`.

**Вариант Б — stdio** (клиент запускает сервер сам; запущен только индексатор):

```json
{
  "mcpServers": {
    "code-index": {
      "command": "C:\\tools\\code-index\\bsl-indexer.exe",
      "args": ["serve", "--path", "main=C:\\Repo1C", "--path", "second=C:\\Repo1C-2"],
      "env": { "CODE_INDEX_HOME": "C:\\tools\\code-index" }
    }
  }
}
```

- Каждая папка из `--path` должна быть перечислена в `daemon.toml` (регистр букв
  в пути не важен). Иначе запрос вернёт `not_started` — «путь не отслеживается
  демоном».
- Алиас в этом варианте берётся из `--path`, а не из `daemon.toml`: клиент ИИ
  указывает именно его. Удобнее задавать те же алиасы, что в `daemon.toml`, но
  это не обязательно.
- Обратные косые черты в JSON удваиваются: `C:\\tools\\...`.
- `env` с `CODE_INDEX_HOME` указывайте обязательно: клиент может не видеть
  переменную из шага 3.

Перезапустите клиент. В списке инструментов должны появиться `get_function`,
`grep_code`, `get_object_structure` и другие.

## Шаг 7. Автозапуск при входе в Windows (по желанию)

Чтобы не держать открытыми окна:

1. В папке `C:\tools\code-index` создайте файл `start-hidden.vbs`:

   ```vbscript
   Set sh = CreateObject("WScript.Shell")
   sh.Run """C:\tools\code-index\bsl-indexer.exe"" daemon run", 0, False
   WScript.Sleep 3000
   sh.Run """C:\tools\code-index\bsl-indexer.exe"" serve --transport http --port 8011 --config ""C:\tools\code-index\daemon.toml""", 0, False
   ```

   Для варианта Б достаточно первых двух строк — последние две (пауза и запуск
   `serve`) удалите.

   Если в пути есть русские буквы — сохраняйте файл в кодировке ANSI (Windows-1251), не UTF-8.

2. Нажмите Win+R, введите `shell:startup`, Enter — откроется папка автозагрузки.
3. Положите туда ярлык на `start-hidden.vbs`.

Запустить сразу, без перезахода в систему, — двойной щелчок по `start-hidden.vbs`.
Окна не появятся; проверка — командой `daemon status` из шага 5.

## Какие файлы появятся

| Где                              | Файл                        | Назначение                                        |
|----------------------------------|-----------------------------|---------------------------------------------------|
| `C:\tools\code-index`            | `daemon.json`, `daemon.pid` | Служебные: адрес и номер процесса индексатора     |
| `C:\tools\code-index`            | `daemon.log`, `serve.log`   | Журналы работы                                    |
| В каждой папке из `daemon.toml`  | `.code-index\index.db`      | Сам индекс                                        |

Если папка с исходниками под git — добавьте `.code-index/` в `.gitignore`.

## Обновление до новой версии

1. Остановите индексатор: `C:\tools\code-index\bsl-indexer.exe daemon stop`.
2. Остановите MCP-сервер: Диспетчер задач → процесс `bsl-indexer.exe` → «Снять задачу»
   (или `taskkill /IM bsl-indexer.exe /F` — завершит все процессы с этим именем).
3. Замените `bsl-indexer.exe` файлом из нового архива.
4. Запустите снова (шаг 5 или `start-hidden.vbs`) и перезапустите клиент ИИ.

## Удаление

1. Остановите оба процесса (см. «Обновление», пункты 1–2).
2. Удалите ярлык из папки `shell:startup`.
3. Удалите папку `C:\tools\code-index`.
4. Удалите переменную `CODE_INDEX_HOME` (окно из шага 3).
5. Удалите папки `.code-index` внутри папок с исходниками.

## Частые проблемы

| Признак | Причина и решение |
|---|---|
| `daemon run` пишет «Переменная окружения CODE_INDEX_HOME не задана» | Переменная не создана или окно открыто до её создания — шаг 3, затем новое окно |
| Ответ `daemon_offline`, в сообщении «CODE_INDEX_HOME не задана для этого процесса» | Клиент ИИ не видит переменную — добавьте `env` в `.mcp.json` (шаг 6, вариант Б) и перезапустите клиент |
| Ответ `daemon_offline`, в сообщении «отсутствует runtime-info файл …daemon.json» | Индексатор не запущен, либо у сервера и индексатора разные `CODE_INDEX_HOME` — запустите `daemon run`, сверьте путь |
| Ответ `not_started` «путь не отслеживается демоном» | Папки нет в `daemon.toml` — добавьте секцию `[[paths]]` и выполните `bsl-indexer.exe daemon reload` |
| Ответ `unknown_repo` | Клиент указал алиас, которого нет у сервера: в варианте А — в `daemon.toml`, в варианте Б — в `--path`. В ответе перечислены доступные |
| При запуске «Обычно разрешается только одно использование адреса сокета … (os error 10048)» | Порт 8011 или 8015 занят (часто — уже запущенной копией программы). Поменяйте порт в команде `serve` / в `daemon.toml` и в `.mcp.json` |
| Клиент не видит инструменты | Сервер не запущен (вариант А) или клиент не перезапущен после правки `.mcp.json` |
| Папка в `daemon status` без `[ready]` | Идёт первая индексация — дождитесь; ход виден в `daemon.log` |

Полное руководство: [README_RU.md](../README_RU.md).
